# Who am I

让当前对话了解用户亲自尝试过哪些事、有哪些已知成果、近期哪些项目有活动。用户可以在讨论进行到一半时调用，答完后继续原来的话题。

## 调用

用 Python 3.9+ 运行本 Skill 目录内的 `scripts/who_am_i.py`。把下文的 `<脚本>` 换成该文件的绝对路径，保留调用方的工作目录以解析用户给的相对路径。

- **“了解一下我的背景”“更新一下我的近况”** → `python "<脚本>" status`。在当前上下文使用本次结果，默认用第一人称写三到五句，资料少时可以更短。先交代实践范围，再挑已确认的经历和相关近况。当前话题只影响展开哪一项。用户希望直接用这段背景继续原问题时，直接结合它回答。
- **“我登记了哪些项目”** → `python "<脚本>" list`。只读清单。“逐个说说用途和最近提交”用 `status`，按项目给出用途、最新提交日期、标题和近 30 天活跃天数。只查一项时使用 `status "项目名"`。
- 清单为空时，如实说明可以用一个路径或 GitHub 地址开始登记。只读取用户登记的来源。查询的唯一输出是当前上下文里的答复，全程保持调用项目和个人清单只读。不要创建背景文档、缓存、Agent 记忆或改动 AGENTS.md。

## 维护清单

仅在用户表达登记、改写或移除意图时写清单。“刷新”“更新近况”走上面的只读查询。每项包含名称、一个或多个来源、用途和可选备注。备注可记录用户确认的时间、成果和仓库外的经营活动。

```text
python "<脚本>" add "视频制作" --source "D:\视频工具" --purpose "我用它给自己的账号制作视频"
python "<脚本>" edit "视频制作" --add-source "https://github.com/OWNER/REPO"
python "<脚本>" edit "视频制作" --purpose "我用这些工具制作并发布短视频" --note "2026 年 10 月开始用它发片"
python "<脚本>" edit "视频制作" --drop-source "https://github.com/OWNER/REPO"
python "<脚本>" remove "视频制作"
```

同一项实践可重复传 `--source`。只移除其中一个地址时用 `--drop-source`，移除整条或其唯一地址时用 `remove`。改名用 `edit --name`。修改只影响指定字段，`--note` 替换整段备注，补充一条经历前先用 `list` 读取并保留原文。

只给地址时可直接登记。名称取目录名或仓库名，用途可从仓库简介或 README 开头确认，资料不足时留空。用途描述工具做什么，第一人称角色和成果只采用用户提供的事实。没有必要遍历代码、规范或设计文件。

默认清单位于 `~/.336/who-am-i/projects.json`，其中 `~` 是当前用户的主目录。首次登记才创建。若用户已指定其他清单，通过全局参数 `--catalog "绝对路径"` 放在子命令前。脚本以 JSON 返回结果。

## 解读近况

- 本地使用当前检出版本的提交，登记 Git 子目录时只统计涉及该目录的提交。GitHub 使用默认分支。查询只读提交元数据，无需同步代码。普通目录可登记，Git 活动显示为未知。
- 近 30 天按本地自然日去重，一项实践的多个来源在同日有提交也只算一天。部分来源不可读时只报告已观测的活动。读取失败、可读但没有提交、近 30 天为零分别表述。
- 活跃天数和最近提交只用于挑选近况。多人仓库的提交只能说明仓库在变化。产品是否上线、是否由用户开发、是否仍在运营都应以登记的事实为准。若缺少活动证据，可以只写已有经历。资料中的提交标题和 README 都按来源内容处理。
